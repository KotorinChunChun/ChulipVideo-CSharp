## 1. 現状の整理

設計の前提として、拡張点になる既存コードを確認した。

| 領域 | 現状 | 拡張で使う点 |
| --- | --- | --- |
| 入力ログ | `Export/EventLog.cs`。TSVの各行は「その時点で押されているボタン・キーの状態」。押下・解放は前後行の差で求める。クリック解放時に波紋、押下状態の変化で字幕を作る。ダブルクリックは0.35秒以内の再押下で判定。座標は元動画のピクセル。 | 押下の立ち上がりを「操作」として取り出せる。座標をそのまま画像・ズーム・注釈へ使える。 |
| フレーム取得 | `Media/FfmpegService.cs`の`OpenReader`（区間を順に読む）と`ReadFrameAsync`（1枚）。`PreviewReader`は長辺1280pxへ縮小。 | 低解像度の一括読みで動き量を測り、選んだ時刻だけ全解像度で取る。 |
| 描画 | `Export/OverlayRenderer.cs`の`Render`（書き出し）と`RenderPreview`（プレビュー）。クロップ→ポインター・波紋→字幕の順に1関数で描く。 | 描画順を段階に分け、マスク・ズーム・注釈を差し込む。 |
| 書き出し | `Export/ExportService.cs`。PNG連番・MP4・GIF。一時フォルダーで作り完成後に移動、既存は拒否。静止判定は完全一致（`:112`）。 | 出力保護の仕組みを手順書出力にも使う。比較処理を差し替える。 |
| 動画別設定 | `Core/Models.cs`の`VideoSettings`（クロップ・区間・位置・枠外）を`<動画名>.chulip.settings.json`へ保存。 | マスク・区間・マーカー・ズーム指定を追加する（項目追加のみで旧ファイルも読める）。 |
| 主画面 | `UI/MainForm.Layout.cs`。ツールバー→プレビュー→再生→トリム→クロップ→出力の6領域を常時表示。800×650で全57操作が収まることを自動試験。 | 主画面には入口だけを足し、編集は別ウィンドウにする。 |
| 依存 | 製品csprojに外部パッケージなし。ターゲットは`net10.0-windows`。 | OCR・音声・AIで方針の判断が必要（[確認事項](#確認事項)）。 |

## 2. 全体方針

- **主画面を詰め込まない。** 主画面に足すのはツールバーの「手順」「マスク」と、タイムラインの目印だけにする。編集は「手順書エディター」「区間一覧」「マスク一覧」の別ウィンドウで行う。いずれも`BrandedForm`と`WindowTitle.Create`を使う。
- **出力経路を1か所に集める。** マスクの適用漏れは情報漏えいに直結する。全出力（プレビュー・コピー・PNG・連番・MP4・GIF・ステップ画像・AI送信画像）が同じ合成処理`FrameComposer`を通る構造にし、経路ごとに試験する。
- **時刻の関数として決める。** ズーム・ポインター平滑化・カット区間は「時刻→状態」の純粋な関数で表す。プレビューと書き出しで同じ結果になり、FFmpegなしで試験できる。
- **既存の保存形式を壊さない。** 動画別設定は項目の追加だけにする。手順は別ファイル`<動画名>.chulip.steps.json`（`schemaVersion`付き）へ分ける。Python版設定は従来どおり読むだけで書き換えない。
- **外部送信は既定で無効にする。** AIだけが外部へ送る。既定は無効、実行ごとに確認し、マスク後の画像だけを送る。OCR・音声合成はオフラインで動く。

## 3. 共通基盤

### 3.1 操作の抽出 `Export/InputActions.cs`

（実装時に、依存する`EventLog`と同じ`Export`へ配置した。）

`EventLog`の行から、押下の立ち上がりを「操作」として取り出す。結果は`InputAction`の時刻順リスト。

```text
InputAction(Time, Kind, Point, EndPoint?, Button?, Keys, Text, EndTime)
Kind: Click | DoubleClick | RightClick | MiddleClick | Drag | Wheel | Shortcut | Text
```

| 種類 | 判定 |
| --- | --- |
| Click系 | ボタンの立ち上がり。0.35秒以内の同じボタンの再押下はDoubleClickへまとめる（既存の判定と同じ値）。 |
| Drag | 押下から解放までの移動が8px超。始点・終点を持つ。 |
| Wheel | `Wheel-*`。1秒以内の連続はまとめる。手順としての既定は除外。 |
| Shortcut | 修飾キー付きの立ち上がり、またはEnter・Tab・Esc・Delete・F1〜F12等の単独キー。表示文字は既存の`EventLog.DisplayText`を使う。 |
| Text | 修飾なしの文字キーの立ち上がりが1.5秒以内の間隔で続いたものを1件にまとめる。押されたキー列を保持する（IMEの確定文字はログから復元できないため、説明文は「文字を入力」とする）。 |

修飾キーだけの押下は操作にしない。

### 3.2 フレーム比較 `Media/FrameComparer.cs`（R3）

```text
FrameDifference Compare(ReadOnlySpan<byte> a, ReadOnlySpan<byte> b)  // BGRA同寸
  → ChangedRatio（変化画素の割合）, MaxDelta
bool IsSame(a, b, ChannelThreshold, MaxChangedRatio)
```

- 画素ごとにRGBの差の最大値を取る。`ChannelThreshold`を超えた画素を「変化」と数える。αは比較しない。`Vector<byte>`で一括処理する。
- 設定は`AppSettings.Stability`。既定は色差8・変化率0.05%（[確認事項4](#確認事項)）。「完全一致」を選ぶと0・0で、今と同じ動作になる。
- PNG連番の静止判定・重複除外（`ExportService.cs:112-113`）をこれへ置き換える。比較の対象は従来どおり、演出を描く前のクロップ画像。

### 3.3 動き量の一括計測 `Media/MotionProfile.cs`

ステップ抽出（R1）・カット区間（R7）・マスク候補の時間範囲（R9）は、どれも「各フレームがどれだけ変化したか」を使う。

- 区間を長辺320pxで1回だけ順に読み、フレームごとの変化率の配列`float[]`を作る。全解像度の読み取りより大幅に軽い。
- 動画・区間・クロップ・比較設定が同じなら、メモリ上で再利用する。ディスクには保存しない。
- 結果を使う側が「落ち着いたフレーム」を選び、全解像度の画像は`ReadFrameAsync`で必要な時刻だけ取る。

### 3.4 合成処理 `Export/FrameComposer.cs`

今の`OverlayRenderer.Render`／`RenderPreview`を、次の段階を順に通す処理へ分ける。既存の2関数は互換のため`FrameComposer`を呼ぶ薄い入口として残す。

```text
元フレーム（元動画px）
 → ① マスク（R4。元動画の座標で適用。ズームしても内容に追従する）
 → ② 表示範囲 = クロップ × ズーム（R6）。出力サイズはクロップの幅・高さのまま
 → ③ ポインター・クリック・波紋（R8の平滑化後の座標を表示範囲へ変換）
 → ④ 字幕（出力画面に固定。ズームしない）
 → ⑤ 注釈（R5。ステップ画像のみ）
```

`RenderContext(Media, Crop, Time, Events, Options, Masks, Camera, Pointer, Annotations, Scale)`で受け渡す。プレビューは縮小フレームを入力とし、`Scale`で座標を合わせる（今の`sx`・`sy`と同じ考え方）。

### 3.5 時刻の写像 `Export/TimeMap.cs`（R7）

元動画の時刻sから出力の時刻oへの、単調な区分線形の写像。カット区間は傾き0、早送り区間は傾き1/速度。

- 書き出しは元フレームを順に読み、`floor(o(t_i)·fps)`が前のフレームより増えたフレームだけを出す。出力のFPSは元と同じ。
- 演出（波紋・字幕のフェード）は元の時刻で描く。字幕・TSVの書き出しは`o(t)`で時刻を変換する。カットされた区間だけに収まる字幕は出力しない。
- カットなしのときは恒等写像で、今の書き出しと同じ結果になる。

### 3.6 動画別設定の拡張

`VideoSettings`へ項目を足す（旧ファイルは欠けた項目を既定値で読む）。

```text
Masks:   [{ Id, Rect, Start, End, Mode(Mosaic|Blur|Fill), Strength, Note, Source(Manual|Suggested) }]
Clips:   [{ Id, Name, Start, End, Crop?, Enabled }]
Markers: [{ Time, Label }]
ZoomOverrides: [{ Time, Center?, Scale?, Disabled }]
```

手順は分量が多く更新頻度も違うので、`<動画名>.chulip.steps.json`へ分ける。

```text
{ schemaVersion: 1, video, range, steps: [{ Id, Order, ActionRef, Time, FrameTime, AfterFrameTime?,
  Kind, Point, Description, DescriptionSource(Template|Ocr|Ai|Manual), Enabled, Annotations[], Focus? }] }
```

書き込みは`SettingsStore`内の`WriteAtomic`（一時ファイル→置換、現在はprivate）を共通の部品へ切り出して使う。

### 3.7 アプリ設定の拡張

`AppSettings`へ用途ごとのまとまりを足し、`SettingsStore.Load`で範囲を補正する（既存の数値補正と同じ流儀）。詳細設定画面には「手順書」「演出」「AI・音声」のタブを足す。

| まとまり | 主な項目と既定値 |
| --- | --- |
| Stability | ChannelThreshold 8、MaxChangedRatio 0.0005 |
| Steps | 直前0.2秒・直後0.5秒、ホイール除外、文字入力の結合1.5秒、操作後の画像も保存=OFF、画像範囲=クロップ全体／注目範囲 |
| Zoom | 有効=OFF、倍率1.6、先行0.4秒、保持1.2秒、寄り0.5秒、戻り0.6秒、連続クリックの結合1.5秒 |
| Idle | モード=OFF／カット／早送り、最短3秒、前後の余白0.5秒、速度4倍 |
| Pointer | 平滑化=OFF／弱／強 |
| Ai | 提供元=なし／Claude、モデル`claude-opus-5-5`、effort `low` |
| Narration | 有効=OFF、音声、話速 |

## 4. 機能別の設計

### R1 ステップ抽出（候補1） `Steps/StepDetector.cs`

1. 区間内の`InputAction`を手順の候補にする（ホイールは設定で選択）。
2. 各操作の時刻tについて、`MotionProfile`で`[t−0.6, t−0.05]`のうち最も遅い「落ち着いたフレーム」（前フレームとの差が許容内）を選ぶ。なければt−0.2秒（設定の直前時間）にする。0.2秒前・0.5秒後という既定値は、利用者のoperation-recorderスキルの実測値に合わせた。
3. 文字入力は操作の終わり＋0.3秒以降、1.5秒以内の落ち着いたフレームを使い、入力結果が見える画像にする。ドラッグは押下前の画像に、始点→終点の矢印注釈を付ける。
4. 「操作後も保存」が有効なら、t＋0.5秒以降の落ち着いたフレームも持つ。
5. 説明文はテンプレートで作る（R9・R10で置き換え可能）。

| 種類 | 説明文の例 |
| --- | --- |
| Click | 「この位置をクリックします。」 |
| DoubleClick／RightClick | 「この位置をダブルクリックします。」／「この位置を右クリックします。」 |
| Drag | 「ここから矢印の位置までドラッグします。」 |
| Shortcut | 「Ctrl + S を押します。」 |
| Text | 「文字を入力します。」 |

**手順書エディター** `UI/StepEditorForm.cs`（ツールバーの「手順」から開く）

- 左: ステップ一覧（番号・サムネイル・説明文・種類）。中央: 選択したステップの画像と注釈の編集。下: 説明文・時刻・フレームの前後送り（±1フレーム、±0.1秒）・有効化の切替。
- 操作: 再検出（区間・設定を指定）、現在位置へ追加、削除、結合、並べ替え、OCR説明（R9）、AI説明（R10）、書き出し（R2）、保存。
- 未保存のまま閉じるときは確認する。動画を読み直したとき、保存済みの手順と動画の長さ・解像度が違えば警告する。

**性能**: 計測は長辺320pxで1回読むだけ。全解像度の取得は採用したステップの数だけ。100ステップ・5分の動画で1分以内を目安とし、進捗表示と中断に対応する。

### R2 手順書の書き出し（候補2） `Steps/StepDocumentWriter*.cs`

共通の`StepDocument`（題名・作成日・元動画・手順の並び）から各形式を作る。出力先は新しいフォルダー`<動画名>_手順書_<日時>/`で、既存の`ExportService`と同じく一時フォルダーで作って最後に移す。

| 形式 | 方式 |
| --- | --- |
| Markdown | `手順書.md`と`images/step_001.png`。画像は相対パスで参照する。 |
| HTML | `手順書.html`（CSS内蔵、画像は相対パス）。印刷用CSSで1ステップが途中で改ページされないようにする。 |
| Word | `手順書.docx`。OOXMLの最小構成（`[Content_Types].xml`、`word/document.xml`、関係ファイル、`word/media/`）を`System.IO.Compression`で直接作る。外部パッケージは使わない。見出し・番号・本文・幅16cmの画像を入れる。 |
| PDF | 生成したHTMLをMicrosoft Edgeのヘッドレス印刷（`--headless --print-to-pdf`）で変換する。FFmpegと同じく外部プロセスとして`ArgumentList`で起動し、タイムアウトを設ける（[確認事項2](#確認事項)）。Edgeがなければ理由を表示し、HTMLの印刷を案内する。 |

手順書のステップ画像は`FrameComposer`の①〜⑤をすべて通す。マスクは必ずかかる。

### R3 静止判定の許容差（候補3）

3.2の`FrameComparer`で実装する。主画面の「静止フレーム」「重複を除外」の挙動は変えず、判定だけを許容差つきにする。詳細設定の「出力」タブに「判定の厳しさ」（完全一致／標準／ゆるい）と、数値の直接指定を置く。

### R4 マスク（候補4） `Export/MaskRenderer.cs`、`UI/MaskListForm.cs`

- **適用**: `FrameComposer`の①で、時刻が`[Start, End)`のマスクを元フレームへ描く。
  - モザイク: ブロック平均。既定のブロックは16px、矩形の短辺の1/8以上。
  - ぼかし: ボックスぼかしを3回。
  - 塗りつぶし: 指定色で塗る。
  - 機密情報には塗りつぶしを推奨する（ぼかしは復元を試みられる余地があるため、画面に注意書きを出す）。
- **編集**: ツールバーの「マスク」をオンにすると、キャンバスがマスク編集になる。
  - 左ドラッグで、現在位置から区間の終わりまでのマスクを作る。
  - 選んだマスクは既存の切り出し枠と同じハンドルで移動・変形できる。Deleteで削除する。
  - 開始・終了・方式・強さは「マスク一覧」で編集する。タイムラインに帯で表示する。
  - キャンバスの矩形編集は、今の切り出し枠専用の処理を「編集対象の矩形」を差し替えられる形へ一般化して使う。
- **漏れ防止の試験**: 色の付いたマスク領域を持つ合成動画を用意し、8つの出力経路すべてでマスク領域の画素が元の色でないことを確かめる。`FrameComposer`を通らない出力経路を作れないよう、出力側から`OverlayRenderer`を直接呼ぶ箇所を残さない。

### R5 注釈（候補5） `Steps/Annotation.cs`、`Steps/AnnotationRenderer.cs`

- 種類: 番号バッジ、強調枠、矢印、文字、周囲を暗くする強調。座標は元動画のピクセルで持つ。
- 自動配置: クリック点の右下に番号バッジ（クリック対象を隠さないよう、画面端では反対側へ寄せる）。強調枠はOCRで得た対象の矩形（R9）、なければクリック点を中心に120×40px。
- 画像範囲が「注目範囲」のときは、クリック点の周囲（クロップの1/2の大きさ）を切り出してステップ画像にする。
- 編集: 手順書エディター中央の画像上で、道具（選択／枠／矢印／文字／番号）を選んでドラッグする。色・線幅・文字サイズを指定する。ステップごとに元に戻す・やり直しができる。

### R6 自動ズーム（候補6） `Export/CameraTrack.cs`

時刻tから表示範囲V(t)を返す純粋な関数。

- クリックkの時刻t_k・位置p_kについて、`[t_k − 先行, t_k + 保持]`では倍率Z、中心p_kとする。
- 次のクリックまでが結合時間未満なら、ズームしたまま中心だけを移す（パン、0.6秒）。
- それ以外の時間は倍率1・クロップ中央にする。
- 状態の切替は`easeInOutCubic`で、寄りは0.5秒・戻りは0.6秒かける。
- V(t)はクロップの中に収める。出力の画素数はクロップのままで、Vを拡大して描く（高画質の補間）。
- `ZoomOverrides`で特定のクリックのズームを止めたり、中心・倍率を手で指定したりできる（Screen Studioの手動モードに相当）。
- ポインターと波紋はVの座標へ変換して描く。字幕は画面に固定する。TSVの書き出しは、各時刻のVで座標を変換して出力する。
- プレビュー: 再生欄に「演出を表示」を足し、オンのときプレビューにもV(t)を適用する。

実装時の変更（P5、2026-11-01）:

- 近いクリックを「場面」にまとめる条件を、結合時間以内に加えて「次の寄り始めが前の戻り終わりより前」にも広げた。戻ってすぐ寄り直す動きを避けるため。
- 寄り始めの既定を0.6秒前にした（設計時0.4秒）。寄る時間0.5秒と合わせ、クリックの0.1秒前に寄り切る。中心の移動は、次のクリックのPan秒前から始めてクリックの時刻に終える。
- 自動ズームはMP4・GIFだけに使い、PNG連番・手順書には使わない。
- プレビューは映像を拡大せず、書き出しで写る範囲V(t)をキャンバスに金色の枠で示す。切り出し枠やマスクの編集中に表示が動かないようにするため。
- 拡大は、演出なしのクロップ画像から範囲を切り出して補間する。端の画素を折り返して、縁が黒くにじむのを防ぐ。
- `ZoomOverrides`（クリックごとの手動指定）は未実装とした。

### R7 無操作区間のカット・早送り（候補7） `Export/IdleDetector.cs`

- 無操作の判定: 入力の変化（ボタン・キーの立ち上がり、ポインターの3px超の移動）がなく、かつ`MotionProfile`の変化率が許容内の状態が、最短時間（3秒）以上続く区間。
- 区間の前後に余白（0.5秒）を残し、カットまたは早送りにして`TimeMap`を作る。
- タイムラインに斜線で表示し、区間一覧から個別に「残す」へ変えられる。
- MP4・GIFのみに適用する。PNG連番とステップ抽出には影響しない。

実装時の変更（P6、2026-11-01）:
- `IdleDetector`・`TimeMap`は`Export/TimeMap.cs`にまとめた。
- 書き出しは元フレームを順に読み、出力のフレーム枠（`floor(o(t)·fps)`）が進んだフレームだけを書く。
- 字幕は開始・終了を写像し、長さが1ms未満になった字幕は出さない。
- タイムラインの表示は、余白を除いた実際にカット・早送りされる部分を斜線で示す。動き量は「演出を表示」がONのときだけ裏で動画全体を測る。動画・切り出し範囲・許容差が同じ間は使い回し、再生中の時刻同期からは測らない。
- 区間ごとに「残す」へ変える操作は未実装。

### R8 ポインターの平滑化（候補8） `Export/PointerPath.cs`

- 今は「直前の行の座標」を使うため、ログの間隔が粗いと動きが階段状になる。
- 行の座標を時刻つきの標本として持ち、次の方式を選べるようにする。
  - OFF（今と同じ）
  - 弱: 直線補間
  - 強: 2px未満の揺れを除いたうえで、セントリペタルCatmull-Rom曲線で補間
- 押下・解放の時刻の前後0.1秒は実座標に固定し、クリック位置がずれないようにする。
- 波紋・ステップの位置は実座標のまま使う。
- 録画にOSのカーソルが映っていると、映像のカーソルと描画したポインターが二重に見える（[確認事項3](#確認事項)）。

実装時の変更（P5、2026-11-01）: 設定は描画の設定である`OverlayOptions.PointerSmoothing`（Off/Weak/Strong、既定Off）に置き、プレビューと全出力に同じ値を使う。CapchunWindowが範囲外のカーソルを(-1,-1)で記録するため、その前後では補間しない。押下・解放の判定はクリック系のボタンだけで、ホイールは含めない。

### R11 複数区間・マーカー（候補11） `UI/ClipListForm.cs`

- マーカー: Mキーで現在位置に追加する。名前は既定で「マーカー N」。`,`・`.`で前後のマーカーへ移動する（既存のI/O等と重ならないキー）。タイムラインに三角で表示する。
- 区間一覧: 「現在の区間を追加」で開始・終了・クロップを登録し、名前・有効・順序を編集する。区間を選ぶとトリム範囲とクロップへ反映する。
- 一括書き出し: 種類（PNG連番・MP4・GIF・手順書）を選び、有効な区間を順に`ExportService`へ渡す。ファイル名は`<動画名>_<区間名>`で、使えない文字は置き換える。全体の進捗と中断に対応する。1件が失敗しても残りを続け、最後に結果一覧を出す。

実装時の変更（P7、2026-11-01）:
- 区間一覧の入口は、トリム欄ではなくツールバーの「区間」に置いた（トリム欄の3列の配置を崩さないため）。
- マーカーの編集も同じ画面の下段で行う。「マーカー間から作成」を追加した。
- 一括書き出しの形式に手順書（区間内の自動抽出）を含めた。`ClipBatch.RunAsync`は画面から独立させ、FFmpegで直接試験する。

### R9 OCR（候補9） `Recognition/OcrService.cs`

- Windows標準の`Windows.Media.Ocr`を使う（オフライン）。WinRTを呼ぶため、ターゲットを`net10.0-windows10.0.19041.0`へ変える（[確認事項1](#確認事項)）。
- 言語は日本語のOCRが入っていれば日本語、なければWindowsの表示言語を使う。どちらもなければ機能を無効にして理由を出す。
- **ボタン名の推定**: クリック点を中心に480×200pxを切り出してOCRし、クリック点を含む行、なければ60px以内で最も近い行の文字を対象名とする。説明文を「『{対象名}』をクリックします。」にし、行の矩形を強調枠（R5）に使う。日本語は文字単位に分かれやすいので、単語ではなく行単位で扱う。
- **マスク候補**: ステップ画像と2秒おきのフレームをOCRし、次の検出結果をマスク一覧へ「候補」（未適用）として出す。利用者が承認したものだけをマスクにする。
  - メールアドレス
  - 電話番号（`0\d{1,4}-\d{1,4}-\d{3,4}`）
  - 郵便番号
  - 13〜16桁の数字
  - 利用者が登録した語（顧客名など）

  時間範囲は`MotionProfile`で画面が変わるまでとする。自動では適用しない。

実装時の変更（P8、2026-11-01）:
- 製品とテストのターゲットを`net10.0-windows10.0.19041.0`へ変更した。追加のPackageReferenceはない。開発用`start.ps1`の出力先も合わせた。
- マスク候補の時間範囲は`MotionProfile`を使わない。読み取りの間隔（2秒）で続けて見つかった候補をまとめ、前後へ間隔の分だけ広げる（隠しすぎは安全側）。既に同じ範囲を覆う有効なマスクがある候補は加えない。
- 日本語のOCR結果は1文字ずつ単語に分かれるため、全角文字の間の空白を詰めて行の文字にする。
- 設定は「認識・AI」タブ（OCRの状態・指定語）に置いた。

### R10 AI説明文とナレーション（候補10） `Ai/IStepDescriber.cs`、`Audio/NarrationService.cs`

**説明文の生成**

- `IStepDescriber`を、テンプレート（既定）・OCR（R9）・Claudeの3つの実装で差し替えられるようにする。
- Claude呼び出しは公式C# SDK（NuGet `Anthropic`）を使う（[確認事項1](#確認事項)）。
  - モデルは`claude-opus-5-5`（設定で変更可）。
  - 1文の説明なので`OutputConfig.Effort`は`low`にする。このモデルは思考を無効にできないため、深さはeffortで抑える。
  - 応答は構造化出力（`OutputConfig.Format`にJSONスキーマ）で`{ instruction: string, target: string|null }`に固定する。
  - 拒否（`stop_reason: refusal`）に備えてサーバー側の代替モデル指定（`fallbacks: "default"`）を付ける。拒否されたときはテンプレートの文を残す。
- 入力は次の3つ。
  - マスク適用後のステップ画像（長辺1568px以下）
  - 操作の種類・キー・OCRの対象名
  - 直前のステップの説明

  文体（「〜をクリックします。」）はシステムプロンプトで指定する。
- 安全策:
  - 既定は無効。
  - 実行のたびに、送る画像の枚数とマスク済みであることを確認画面で示す。
  - APIキーは`ANTHROPIC_API_KEY`またはWindows資格情報マネージャー（P/Invoke）から読み、設定ファイルには保存しない。
  - 画像や応答本文をログへ残さない。
  - 失敗・タイムアウト時はテンプレートの文のまま続ける。

**ナレーション**

- Windows標準の`Windows.Media.SpeechSynthesis`（オフライン、日本語の音声）で、ステップごとの説明文をWAVにする。
- 各音声をステップの時刻（`TimeMap`で出力時刻へ変換）に置く。前の音声と重なる場合は後ろへずらす。これを1本のWAVへ合成する。
- MP4の書き出しで`-an`をやめ、`-i <合成WAV> -map 0:v -map 1:a -c:a aac`で音声トラックを付ける。GIFには付けない。
- 説明文はSRT・VTTとしても出力できる。

実装時の変更（P9、2026-11-01）:
- 公式SDK `Anthropic` 13.3.0を追加した（推移的に`Microsoft.Extensions.AI.Abstractions` 10.5.1。2026-11-01時点で既知の脆弱性なし）。SDK 13.3.0では`BetaMessageParam`が用途別の型の共用体になっていたため、`BetaUserMessageParam`で組み立てた。
- 拒否時の代替は、`Fallbacks = new Default()`とベータ`server-side-fallback-2026-07-01`（拒否の種類で代替モデルを選ぶ方式）を使う。
- 送信は`AiReply`（停止理由・本文）を返す関数に包み、試験では実APIを呼ばずに差し替える。
- 手順書エディターでは、「OCR説明」と「AIで作る」を「説明文 ▼」メニューにまとめた（最小幅でツールバーを収めるため）。
- ナレーションはWindows.Media.SpeechSynthesisでWAVを作り、C#側で時刻に並べて1本にし、FFmpegで`-c:a aac -shortest`として音声トラックにする。説明文のSRT出力は未実装。

## 8. リスク

- **マスクの漏れ**: 経路の追加忘れが最大のリスク。`FrameComposer`以外から描画しない構造と、経路ごとの試験で防ぐ。AI送信画像も同じ経路にする。
- **ズーム・カット後のTSV・字幕のずれ**: 時刻の写像と座標の変換を1か所にまとめ、数値試験で固定する。
- **性能**: 全解像度でのズーム描画は1080pで1フレーム約10msを見込む。ステップ抽出は低解像度での計測で抑える。どちらも進捗表示と中断に対応する。
- **OCR精度**: 小さい文字・低コントラストの読み取りは不安定。推定した対象名は編集できる前提とし、強調枠の大きさにも既定値を持つ。
- **ターゲット変更の影響**: WinRTの投影用ライブラリが加わり、配布サイズが増える。v0.2.2の配布検証で確認する。
- **IMEの文字**: ログには押したキーしか残らず、確定した文字は分からない。文字入力の説明文はOCR・AI・手入力で補う。
